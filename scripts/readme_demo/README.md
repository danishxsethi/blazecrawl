# README demo generation

Reproducible tooling for the README's visual product demos.

**Truthfulness standard:** every line displayed with a `$` shell prompt is
actually executed. Architectural captions are explicitly presented without a
shell prompt. All product output shown comes from real BlazeCrawl execution
against a disposable, loopback-only instance — no output is fabricated, no
credentials are shown, and no external SaaS is used.

## What this produces

| Asset | Flow | File |
|---|---|---|
| Hero | launch → `/health` → scrape a page → Markdown | `docs/assets/blazecrawl-hero.gif` |
| Map → Crawl | `blazecrawl map` → `blazecrawl crawl --wait` | `docs/assets/blazecrawl-map-crawl.gif` |
| Security | egress diagram + real allowed/blocked responses | `docs/assets/blazecrawl-security.gif` |
| MCP | real `tools/list` + `tools/call scrape` over stdio | `docs/assets/blazecrawl-mcp.gif` |

Each GIF also gets a poster PNG (`docs/assets/blazecrawl-<name>.png`) for
fallback/social use.

## Prerequisites

Required tools (all OSS, no proprietary software):

- **Docker** — runs the disposable demo instance.
- **asciinema** — records the terminal session (`pipx install asciinema` or
  `pip install asciinema`).
- **agg** — renders the `.cast` to GIF. Use the static musl build on older glibc:
  <https://github.com/asciinema/agg/releases> (`agg-x86_64-unknown-linux-musl`).
- **gifsicle** — optimizes GIFs (`apt install gifsicle`).
- **ffmpeg** — extracts poster frames (`apt install ffmpeg`).

A Python 3.12 venv providing the `blazecrawl` CLI and `blazecrawl-mcp` server
(used by the map-crawl and mcp demos):

```bash
uv venv --seed --python 3.12 /tmp/blazecrawl-demo-cli
/tmp/blazecrawl-demo-cli/bin/pip install blazecrawl-core==0.1.2 blazecrawl-mcp==0.1.2
```

## Regenerate everything

```bash
export AGG=/path/to/agg-musl
export BLAZECRAWL_CLI_VENV=/tmp/blazecrawl-demo-cli
bash scripts/readme_demo/render.sh     # start instance, record, render raw GIFs
bash scripts/readme_demo/optimize.sh   # optimize into docs/assets/ + poster PNGs
```

`render.sh` orchestrates two phases:

1. **Hero (self-contained).** `session_hero.sh` itself runs the visible
   `docker run` command against the published image on `127.0.0.1:8000`, reads
   the generated local key from the container's first-run log line into a
   variable **without printing it**, waits for `/ready`, calls `/health` and
   `/v1/scrape`, then removes its own container and volume (via a shell trap).
   The container serving the visible requests is the one the visible command
   started.
2. **Shared instance for the rest.** A disposable container is started on
   `127.0.0.1:8010` with an obviously non-secret demo key
   (`blz_local_readme_demo`) for the map/crawl, security, and MCP sessions, and
   removed afterward.

Approximate generation time: ~2–3 minutes (plus a one-time image pull).

## How it works

- The four `session_*.sh` scripts are recorded by asciinema. They type commands
  with realistic pacing and **execute every `$` command for real**; JSON
  responses are piped through `python3`/`jq` only to select and format fields —
  the underlying bytes are the server's actual output.
- `run_mcp_demo` is the executable command shown in the MCP GIF. It only invokes
  `mcp_demo_client.py`, a minimal, standards-compliant MCP stdio client that
  drives a real `initialize → tools/list → tools/call` exchange against a real
  `blazecrawl-mcp` server. No LLM is involved or implied.
- The security demo pairs a labeled architectural **diagram** (resolve →
  validate → pin → connect, presented as plain caption text, not a shell
  command) with **real** allowed/blocked responses. The diagram is not
  packet-level telemetry.

## Notes / honest limitations

- The hero runs on `127.0.0.1:8000`; the map/crawl, security, and MCP demos run
  against a shared loopback instance on `127.0.0.1:8010`. The README quickstart
  uses the default `8000`. The flow is identical.
- The hero's local API key is generated by the container on first run and read
  from its logs into a variable; it is never printed. The shared instance uses a
  documented placeholder key (`blz_local_readme_demo`) that satisfies the key
  format, is loopback-only, and is never a real credential. No frame shows a key
  value.
- `quotes.toscrape.com` is used for the map/crawl demo because it is a stable
  public site designed for scraping practice; `example.com` is used for the
  single-page scrape.
